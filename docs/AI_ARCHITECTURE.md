# معماری و جریان امن هوش مصنوعی (AI ARCHITECTURE & WORKFLOW)

در سامانه **NIRWARE NEXT**، قابلیت‌های هوش مصنوعی بر پایه دو ستون اصلی طراحی شده‌اند:
1. **استخراج ماشینی اسناد فیزیکی و قبوض باسکول (AI Document Extraction)**
2. **دستیار تحلیلی و مدیریتی کارخانه (Tool-Based AI Assistant)**

هر دو قابلیت با رعایت اصل بنیادین عدم دسترسی مستقیم و آزاد مدل هوش مصنوعی به پایگاه داده و الزام به نظارت انسانی پیاده‌سازی شده‌اند.

---

## ۱. چرخه استخراج هوشمند با نظارت انسانی (Human-in-the-Loop Document Extraction)

```text
  [ تصویر فیش باسکول / PDF بارنامه ]
                 │
                 ▼
      [ ۱. اعتبارسنجی اولیه فایل ]
         - چک حجم (حداکثر ۱۰ مگابایت)
         - چک MIME Type (JPEG, PNG, WebP, PDF)
                 │
                 ▼
      [ ۲. پردازش سرور با Gemini ]
         - فراخوانی مدل @google/genai در Express
         - ارسال پرامپت مهندسی‌شده فارسی
         - دریافت داده در ساختار JSON استاندارد با ابزار Type Schema
                 │
                 ▼
      [ ۳. اعتبارسنجی و نرمال‌سازی ]
         - جداسازی قطعی نام فروشنده از نوع کالا (مثلاً "احمدی" از "ذرت")
         - محاسبه نمره اطمینان (Confidence Score)
         - تبدیل ارقام فارسی به انگلیسی
                 │
                 ▼
      [ ۴. رابط کاربری بازبینی انسانی (Human Review Modal) ]
         - نمایش فرم پرشده به کاربر باسکول
         - کاربر مقادیر را با اصل تصویر مطابقت داده و در صورت نیاز ویرایش می‌کند
                 │
                 ▼
      [ ۵. کلیک کاربر روی «تایید نهایی و ثبت» ]
                 │
                 ▼
      [ ۶. درج امن در PostgreSQL درون تراکنش ACID ]
```

### قانون امنیتی غیرقابل مذاکره:
> **هیچ مدل هوش مصنوعی حق نوشتن مستقیم داده در پایگاه داده، تغییر موجودی انبار یا صدور سند مالی بدون کلیک تایید توسط کاربر انسانی را ندارد.**

---

## ۲. دستیار هوشمند مدیریت با الگوی فراخوانی ابزار (Tool-Based AI Assistant)

برای پاسخ به سوالات تحلیلی مدیران کارخانه (مانند: *"موجودی کنجاله سویا چقدر است؟"* یا *"کدام گله‌ها ضریب تبدیل نامناسب دارند؟"*):
- مدل هوش مصنوعی به هیچ وجه کوئری خام SQL روی دیتابیس اجرا نمی‌کند.
- دستیار صرفاً به مجموعه‌ای از **توابع ابزاری فقط-خواندنی (Read-Only Tools)** با اعمال دسترسی نقش کاربر متصل است:

| ابزار مجاز (Allowed Tool) | ورودی‌ها | خروجی بازگردانده شده به مدل |
| :--- | :--- | :--- |
| `getInventorySummary()` | `productId?` | موجودی فعلی، ورودی‌های امروز، حداقل موجودی هشدار |
| `getFlocksPerformance()` | `flockId?` | سن گله، درصد تلفات، سهمیه مصرف‌شده، ضریب تبدیل FCR |
| `getPendingOrders()` | `farmerId?` | سفارش‌های در انتظار تایید، در انتظار تولید و در مسیر |
| `getDailyProduction()` | `date` | تناژ تولید شده به تفکیک نوع دان و مواد اولیه مصرفی |
| `getLowStockAlerts()` | - | فهرست اقلامی که موجودی آنها زیر آستانه بحرانی است |

این معماری مانع از نشت اطلاعات، حملات Prompt Injection برای استخراج داده‌های سایر کاربران، یا اجرای دستورات مخرب دیتابیسی می‌گردد.
